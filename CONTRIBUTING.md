# Contributing

We welcome contributions that improve the project, including new features, bug fixes, UI/UX improvements, BLE functionality, performance, documentation, and tests.

---

## Quick Guide

1. Create a feature branch.
2. Make your changes.
3. Test locally.
4. Commit your changes.
5. Push your branch.
6. Open a Pull Request.

---

## Branch Naming

Use descriptive branch names:

```text
feature/feature-name
fix/issue-name
docs/documentation-name
refactor/module-name
test/test-name

```

## Commit Convention

Use clear and meaningful commit messages:
```
feat: add BLE device discovery
fix: resolve offline message sync
refactor: improve chat service
docs: update API documentation
test: add authentication tests
```

## Development

Recommended editors:

```
Visual Studio Code
Android Studio
```
Use Flutter and Dart extensions with formatting, linting, debugging, and Git support enabled.

Follow the existing project architecture, keep features modular, and write clean, reusable code.


## Suggestions

For new ideas or improvements:

Create an issue.
Clearly describe the proposed change.
Add screenshots or examples when useful.
Discuss major changes before implementation.

## Security

Do not commit:
```
.env
API keys
Passwords
Private credentials
Production secrets
```
For security vulnerabilities, report them privately instead of posting sensitive details publicly.


## Pull Requests

A Pull Request should include:
```
Title
Description
Related issue
Testing details
Screenshots (for UI changes)
```
Keep Pull Requests focused, clean, and easy to review.

## Code Review

All Pull Requests should be reviewed before merging. Address review feedback and keep your branch updated with the latest changes.
